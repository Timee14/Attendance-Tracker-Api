# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Uses naive datetimes; does not truncate sub-seconds (R1); ignores overnight shift boundaries; misses timezone awareness. | Input `09:40:00.900` treated as late; fails on UTC/IST mismatches. | Converted UTC instant to IST, truncated to whole seconds (R1), resolved shift start relative to shift date, and applied strict 10-min grace floor calculation (R2). |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round()`, which applies banker's rounding (round-to-even) instead of exact half-up rounding (R4, R8). | Input with 9.125 yielded 9.12 instead of 9.13. | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44–47) | Does not enforce 30-minute minimum threshold (counts 1–29 min as overtime); fails on overnight shifts where `shift_end` is on next calendar day. | Punch-out 10 minutes past shift end returned 10 overtime minutes instead of 0. | Computed shift end date (next calendar day for overnight), evaluated floor minutes, and returned overtime only if `>= 30`. |
| 4 | `health` (lines 72–74) | Returns static `{"status": "ok"}` without running a MongoDB ping; never returns 503 when the database is offline. | Stopping MongoDB daemon still returned 200 OK. | Executed `db.command("ping")` in try-except block, returning 503 on database unavailability. |
| 5 | `create_employee` (lines 78–85) | Check-then-insert race condition; missing validation for `shift_start != shift_end`; `created_at` returned as naive datetime instead of epoch ms; missing unique index. | Concurrent POST `/employees` with same `emp_code` created duplicate records; timestamps serialized as strings. | Added unique index on `emp_code`, caught `DuplicateKeyError` to return 409, validated shift inequalities, and converted `created_at` to epoch ms. |
| 6 | `list_employees` (lines 88–96) | Pagination off-by-one: `skip = page * page_size` skipped the first 20 records on page 1; `total` counted the whole collection instead of the filtered subset; lacked sorting. | Requesting `page=1` returned items 21–40; department filter returned total count of unfiltered collection. | Corrected skip formula to `(page - 1) * page_size`, passed query filter `q` to `count_documents(q)`, and added `.sort("emp_code", 1)`. |
| 7 | `punch_in` (lines 99–122) | Check-then-insert race condition; missing employee existence check (no 404); naive timezone conversion; failed to handle overnight shift date attribution; exposed internal `_id` as `id`; missing status enum validation. | Concurrent duplicate punch-ins created multiple records; punching in for non-existent employee succeeded or crashed; invalid statuses accepted. | Added unique compound index on `(emp_code, date)` returning 409 on `DuplicateKeyError`, validated employee existence (404), resolved overnight shifts (R1), validated status enums, and sanitized output. |
| 8 | `list_attendance` (lines 124–151) | Loaded entire collection into memory with `list(db.attendance_logs.find(q))` and sorted in Python (memory exhaustion at 100k records); missing `date_from > date_to` validation (422); missing secondary sort on `emp_code`; exposed `_id` as `id`. | High memory consumption and severe latency on large datasets; passing `date_from > date_to` returned empty list instead of 422. | Delegated sorting and pagination to MongoDB cursor with `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`, validated date ranges (422), and cleaned document serialization. |
| 9 | Application Lifecycle & Indexes | No startup lifecycle handler; no database indexes configured. | All queries performed full collection scans (`COLLSCAN`). | Implemented FastAPI `lifespan` handler creating all required unique and compound indexes idempotently at startup. |
| 10 | Missing Contract Endpoints | Seven contract endpoints were missing (`POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/admin endpoints). | Invoking missing routes returned 404. | Implemented all endpoints adhering to OpenAPI schemas and aggregation rules. |

### Investigated Items Decided NOT to be Defects
* **String representation of `emp_code`:** `emp_code` is a customer-defined business identifier (e.g. `EMP0001`) and is intentionally maintained as a string separate from MongoDB's internal `_id`.
* **Absence of documents for unrecorded days:** Weekdays without documents are intentionally distinct from documents with status `ABSENT` (representing unrecorded days vs explicitly logged absences).
